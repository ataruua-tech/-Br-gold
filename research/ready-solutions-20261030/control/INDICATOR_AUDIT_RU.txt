ПРОВЕРКА ЗАВИСИМЫХ ИНДИКАТОРОВ OSENGINE
Версия источника: 09b0eefc7ac6cf5a73e461cc3a81ded9c34cd54b.
Статус данного файла: разбор кода и независимый расчёт индикаторов; НЕ отчёт
о компиляции всей платформы, исполненных сделках или прибыльности.

Зависимости A: SuperTrend_indicator -> ATR. Робот устанавливает Median,
длины10/50, отклонение1, Use candle shadow=false. Последний флаг отличается
от собственного default индикатора и обязателен для точного воспроизведения.
Прогрев робота: Count>=60, т.е. первый допущенный индекс59 (нумерация с0).
Линии начинают заполняться на индексах10/50 соответственно. ATR включает
нулевой TR первого бара в исходную среднюю; дальнейшая рекурсия округлена
до9 знаков. Индикатор использует строгие сравнения и close для переключения
направления; средняя точка всё равно (high+low)/2. Отдельного стопа у A нет.

Зависимости B: Bollinger -> Sma; отдельно RSI. Sma суммирует через ScriptSpells
индексы startIndex+1..endIndex. Поэтому SMA21 включает последние21 close.
Bollinger21 впервые рассчитывает полосы на индексе22: на0..21 полосы0,
на22 впервые значение. Дисперсия делится на21,
не на20; ветка деления наN-1 применяется только для Length>30. Полосы округлены
до6 знаков, промежуточные квадраты/корень проходят decimal/double преобразования.

RSI14 НЕ совпадает с обычным непрерывным Wilder RSI. Для каждого индекса>=35
он заново берёт35 последних изменений. Начальная средняя = первые15 изменений
/14, затем20 рекурсий alpha1/14. Итог округлён до2 знаков. При нулевом среднем
росте ИЛИ падении возвращается100. Поэтому полностью падающая серия после
прогрева тоже даёт100. До индекса35 значение остаётся0: на16..34 в цикле есть
только14 изменений, но первичная MovingAverageHard запускается на15-м.

Проверка прогрева B в самом роботе недостаточна: Count>=21 и сравнение с
BollingerDeviation вместо готовности RSI. Это имеет фактическое проявление
в предоставленных BRX6 H1: индекс25, begin01.07.2026 19:00, граница20:00 МСК.
prevLow74.11 < предыдущая нижняя74.121049;
low74.29 > текущая нижняя74.094977; RSI0 <30.
Авторский код удовлетворяет условию Buy при неготовом RSI. Исправление не
внесено: исходный контроль обязан сохранить дефект. Возможная отдельная новая
версия — блокировать входы до готовности обоих индикаторов; не объявлять её
исходным кодом и не выбирать по улучшению доходности уже просмотренной истории.

Защита B: на закрытии свечи для уже открытой позиции вычисляет low*0.99 для
Buy либо high*1.01 для Sell. CloseAtTrailingStopMarket сохраняет только более
строгий уровень (для Buy выше, для Sell ниже), без округления raw уровня по
тик-сайзу. StopIsMarket=true. Это внутреннее состояние тестера, не доказательство
биржевого защитного поручения. В классе нет установки защиты одновременно
с входом. Промежуток от исполнения входа до следующего события надо измерить
по нативному журналу, а не предположить защиту внутри входной свечи.

BotManualControl constructor defaults: StopIsOn=false,ProfitIsOn=false,
DoubleExitIsOn=true,SecondToOpenIsOn=true,SecondToCloseIsOn=true,50сек.
После конструктора возможен Load старого Engine/{name}StrategSettings.txt.
Поэтому изоляция и фиксация всех флагов существенны. В чистой конфигурации
внешняя защита платформы не устраняет пробел исходного B.

ФАЙЛЫ
independent_indicators.py — формульный проверятор, без сетевого/торгового кода.
test_independent_indicators.py — синтетические/граничные проверки и контроль
конкретных исходных свечей. Данные в independent-checks/ извлечены без изменения
из source_2026, собственные SHA256 сохранены в metadata результатов.
*-expected.jsonl — полные побарные значения, условия и готовность.
Округление ROUND_HALF_EVEN; Decimal50digits не объявлен побитовым эквивалентом
96-битного C# decimal. Допуски финального сравнения:ATR/ST1e-9,BB1e-6,RSI0.01.
Направление/условия должны совпасть точно. Расхождение около границы нельзя
скрыть округлением. Сверка с нативным тестером ещё должна быть выполнена.
